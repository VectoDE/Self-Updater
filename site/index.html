Each update runs these steps in order

  1. 1Repository

    Where the code comes from.

  2. 2What to deploy

    The newest commit of the branch, or the newest release tag.

    Follow

  3. 3Checkout and install

    The directory your service runs from. The updater creates it on the first run.

  4. 4Before the switch

    Runs in the workspace before the new code is checked out. If it fails, nothing changes.

  5. 5Restart

    How the new version starts.

  6. 6Health check

    Proves the new version works. Leave both empty to skip it.

  7. 7Finish or roll back

    After a successful check the post-update command runs. After a failure the previous commit comes back.
